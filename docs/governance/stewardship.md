# Ongoing stewardship

The maintainer requested ongoing conceptualization, management, implementation,
and growth through OpenSteward. A weekly review in the originating Codex chat
uses research-project-direction, deliver-engineering-slice, and
govern-project-evidence skills. The installed offline portfolio audit is not
represented as a live GitHub automation service.

Each cycle reads repository state, CI, issues, open PRs, architecture, roadmap,
and evidence. Prefer repairing an existing open slice over creating competing
work. While the initial three MVP PRs remain open, keep fixes within that stack.
Afterward, select one bounded improvement aligned with approved roadmap goals,
define acceptance criteria, implement and verify it, and prepare a draft PR.

Use primary-source research for consequential decisions. Update architecture,
roadmap, and evidence when supported by accepted scope. Ask the maintainer when
a proposal needs a new product direction, unavailable integration infrastructure,
or broader authority. A research finding alone is not implementation approval.

Do not merge, release, deploy, purchase services, install heavyweight simulators,
change credentials, or contact third parties autonomously. Public pushes and
draft PRs for the requested project stewardship are authorized. Preserve truthful
attribution, private state, and repository isolation. Notify only for a meaningful
improvement, failure, blocker, or required decision; stay quiet on unchanged state.

The repository records this policy, not a guarantee of perpetual unattended
operation. The Codex scheduled chat must remain enabled and have access to the
local checkout and GitHub. No scheduler credentials belong in this repository.
